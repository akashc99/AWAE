Common Security Regex Patterns

These are starting points for finding potential vulnerabilities using regex. Real-world patterns often need refinement based on language, frameworks, and context. Manual review is crucial.

PHP Specific

Find common superglobals (Input Points)
\$_(GET|POST|REQUEST|COOKIE|SESSION|FILES|ENV|SERVER)\[.*?\]
Find common command execution functions
\b(system|exec|shell_exec|passthru|proc_open|popen|pcntl_exec)\s*\(
Find PHP eval or assert (Potential Code Injection)
\b(eval|assert)\s*\(
Find dynamic file inclusion (Potential LFI/RFI)
\b(include|require)(_once)?\s*\(?\s*['"]?\s*\$?_?(GET|POST|REQUEST|COOKIE)\b
Find unserialize (Potential Object Injection)
\b(unserialize)\s*\(
Find weak random number generators (Avoid for security contexts)
\b(rand|mt_rand)\s*\(
Find basic path traversal patterns in file functions
\b(file_get_contents|fopen|include|require)(_once)?\s*\(?\s*['"].*?(\.\.\/|\.\.\\\\)

SQL Injection Related

Find simple SQL keywords in strings (basic check)
["'`]\s*(SELECT|INSERT|UPDATE|DELETE|UNION|DROP|ALTER)\b[^"'`]*["'`]
Find SQL keywords in strings potentially concatenated with input
["']\s*\b(SELECT|UPDATE|INSERT|DELETE)\b.*?\s*["']\s*\.\s*\$?_(GET|POST|REQUEST|COOKIE)\b|\$?_(GET|POST|REQUEST|COOKIE)\b\s*\.\s*["']\s*\b(SELECT|UPDATE|INSERT|DELETE)\b
Find sprintf/printf with potential user input and SQL keywords (Potential SQLi)
\b(sprintf|printf)\s*\(.*?["'].*?(SELECT|UPDATE|INSERT|DELETE)\b.*?%[sd].*?["'].*?,\s*\$?_(GET|POST|REQUEST|COOKIE)\b

Cross-Site Scripting (XSS) Related

Find direct echo/print of superglobals (Potential XSS)
\b(echo|print)\b\s*\(?\s*.*?\$_(GET|POST|REQUEST|COOKIE)\b
Find common template markers in output (Potential SSTI/XSS)
[> ]({{.*?}}|{%.*?%}|<%=?.*%>)[\s<]

Java Specific

Find Java Runtime.exec (Potential Command Injection)
\bRuntime\.getRuntime\(\)\.exec\s*\(
Find Java ObjectInputStream (Potential Deserialization)
\bObjectInputStream\s*\(
Find Java XML Parsers (Check configuration for XXE!)
\b(XMLReader|DocumentBuilder|SAXParser|SAXReader|XMLInputFactory)\b

Python Specific

Find Python exec/eval (Potential Code Injection)
\b(exec|eval)\s*\(
Find Python os.system/subprocess (Potential Command Injection)
\b(os\.system|subprocess\.(call|run|Popen))\s*\(
Find Python pickle.load(s) (Potential Deserialization)
\bpickle\.load(s)?\s*\(
Find Python Flask/Jinja template markers (Potential SSTI)
{{.*?}}|{%.*?%}

General Patterns

Find hardcoded credentials/secrets (Simple check, high FP rate!)
\b(password|secret|passwd|api_?key|token|pwd)\b\s*[:=]\s*["'].{5,}?["']
Find common SSRF triggers (Functions making HTTP requests)
\b(curl_exec|file_get_contents|fsockopen|Http(Client|Request)|requests\.(get|post)|urllib\.request\.urlopen)\s*\(.*?['"]https?:\/\/
Find comments (May contain sensitive info)
\/\/.*|#.*|\/\*[\s\S]*?\*\/|

Remember: Regex is a powerful tool for initial scanning, but findings always require manual review to confirm vulnerabilities and understand context. Patterns often need adjustment based on the specific language, framework, and coding style.
